# V3.5 lifecycle — independent real-GitHub RED oracle

**Governing:** Common #787 → #864 → #875; lab #6. This is a **non-authorizing provider-observation contract**, not a new DELP projector or task-evidence source. Its purpose is to expose the gap between created parent/child issues and a working Owner-intent-to-successor lifecycle.

Run with a scoped **GITHUB_TOKEN**: `python scripts/lifecycle_acceptance_observer.py --repository reallaksh19/relay-v35-e2e-lab`. The workflow uploads `LIFECYCLE_ACCEPTANCE.json` even when the observer returns **exit code 3** for lifecycle RED. Exit 2 means provider unavailable/misconfigured: UNKNOWN, never PASS.

## Meaning of observed statuses

- `LAB_ONLY_PASS`: exact mirrored synthetic seed, not original chat authority.
- `MISSING`: required GitHub/provider material not found after complete observed pagination.
- `HOLD_NO_APPROVED_GRAPH`: no native graph selection observed; never infer approval.
- `NEEDS_NATIVE_REPLAY`: a marker/file is present, NOT accepted until native V3.2/V3.5 projection/source/scoreboard verification.
- `NOT_RUN`: genuine reviewer/cold successor/adversarial execution not attempted.
- `RED_NOT_END_TO_END_QUALIFIED`: no complete lifecycle assertion.

The `observation_sha256_not_delp_snapshot` is just a reproducible provider-observation hash; **never publish it as native DELP identity or P/E**.
