# RNR-07 golden prompts — HOW they were constructed and WHAT is required

Golden fixtures:
- [Stage 1 independent prompt](../fixtures/runner_benchmark/STAGE1_GOLDEN_PROMPT.md)
- [Stage 2 reconciliation prompt](../fixtures/runner_benchmark/STAGE2_GOLDEN_PROMPT.md)

**Golden** means frozen, falsifiable prompt contract, not successful model performance or production protocol adoption.

## HOW the two prompts were developed

First, preserve the Owner's exact conceptual task: an independently preparing successor begins when the predecessor has consumed about 70% of usable life; it knows the Owner's original WHAT/WHY, starting source and pending/parked work but **not HOW** the predecessor implemented it. After independent Stage 1 freezes, Stage 2 compares actual code, claims and evidence. Alternative hypotheses at 50% and 85% are experimental conditions. This must not be conflated with DELP execution health, programme progress or writer permission.

Second, separate the information privileges: Stage 1 gets only allowlisted source-pinned originals and golden fixture; all current Git commits, PRs, tests, implementation plans and predecessor handovers are withheld. The prompt explicitly requires UNKNOWN rather than plausible invented details. A typed independent plan and exactly three questions must be frozen before any Stage 2 live-source disclosure. The harness enforces bytes and freeze ordering, while real agent file/network sandboxing remains an external gate.

Third, Stage 2 asks for *source-verified reconciliation*, not agreement with Agent A: read current SHA, test evidence and source-level downstream consumers; compare competing plans with ROI classifications ABSORB (already done), INTEGRATE (missing high ROI within scope), REPAIR (contradiction), PARK (medium with rationale and revisit trigger), DECLINE (low ROI), OWNER_DECISION_REQUIRED (new or disputed scope). The predecessor's answer is a claim until corroborated.

Fourth, turn failure modes seen in the V3.5 lifecycle into falsifying oracles: old-head facts, false P/E title, unapproved Owner revision, unrelated R2 changes, missing native DELP integration, no Chromium evidence, unknown write, untrusted Owner comment and workflows where no tests ran. Prompt success must not be measured by impressive prose; it must identify the correct stop action, source ref and authorization boundary.

Fifth, test prompt robustness through adversarial controls. Neither prompt includes hidden expected flags. The harness rejects a tampered Stage 1 packet, modified frozen plan, missing or extra fields, wrong source refs, invalid Owner/writer claims, duplicate trial and unsupported telemetry. A model must not become its own independent reviewer or provider oracle.

## WHAT robust prompts require

| Requirement | Reason | Objective check or open gap |
| --- | --- | --- |
| Lossless Owner purpose, exact original commit and authentication grade | Avoid task drift | Synthetic source clearly labeled, true private Owner authentication OPEN |
| Original semantic responsibility and plan authority | Preserve denominator and split | Explicit original scope; Owner-approved changes require separate evidence |
| Enforced Stage 1 access barrier | Avoid copied or contaminated reconstruction | Allowlisted packets and freeze tests; true sandbox OUTSIDE harness |
| Independent WHY/WHAT, not Agent A HOW | Recover intent rather than mimic implementation | Stage 1 prompt forbids predecessor implementation sources |
| EXACT current head, tests and consumer call graph | Detect patchwork and stale checks | Stage 2 must cite actual source/browser evidence; real browser trials OPEN |
| Emergency predecessor crash path | No terminal handover may exist | Stage 2 reconstructs material without inventing Agent A claims |
| Typed three-question frozen plan | Enable objective reconciliation | Stage 1 schema + SHA256 receipt before Stage 2 |
| ROI handling, parked Medium and Owner decisions | Avoid opportunistic redesign or backlog disappearance | Explicit Stage 2 disposition vocabulary and revisit triggers |
| Epoch, unfinished provider writes, old-agent revocation | Prevent concurrent GitHub writers | HOLD on UNKNOWN; real GitHub credential-custody gate OPEN |
| Source-ref-backed negative as well as positive tests | Avoid easy synthetic green results | 8 hidden oracles; actual independent trials NOT RUN |
| Matched multi-arm interruption and cost study | Test the 70% hypothesis rather than assume it | 7 conditions, seeded 3 repeats, external telemetry required |
| No self-written progress, merging or approvals | Preserve V3.5/DELP/Local authority | Both prompts read-only; scorer disqualifies unapproved claims |

## Freeze and revision policy

Treat each prompt and scenario file version as immutable test input for a campaign. SHA-pin every prompt, original source and Stage 1 packet. Prompt or rubric changes require a new version and all conditions re-run, not selective tuning to a model answer. The oracle is never mounted in a successor's context. Integrity digests alone do not prove a separate model principal, user/Owner consent or provider custody.

No actual model comparison, ROI superiority, Chromium test, independent review or production V3.5 gate completion is claimed by these fixtures.
